## Why is this dataset difficult?

Fraud is usually a very small minority of all transactions.

For an imbalanced dataset, a model could achieve very high accuracy simply by predicting almost every transaction as legitimate.

For that reason, this project reports:

### ROC-AUC

Measures how well the model separates fraud from legitimate transactions across different thresholds.

### PR-AUC

The Precision-Recall curve is particularly useful for rare-event classification because it focuses on precision and recall for the positive class.

### Precision

Of the transactions flagged as fraud, how many were actually fraud?

```text
Precision = TP / (TP + FP)
```

### Recall

Of all actual fraudulent transactions, how many did the model detect?

```text
Recall = TP / (TP + FN)
```

## SMOTE

SMOTE stands for **Synthetic Minority Over-sampling Technique**.

It creates synthetic examples of the minority class instead of simply duplicating existing fraud examples.

Important:

```text
Original dataset
       ↓
Train/Test Split
       ↓
SMOTE → TRAINING DATA ONLY
       ↓
XGBoost
       ↓
Original untouched TEST DATA
       ↓
Evaluation
```

Applying SMOTE before the train/test split can leak information from the test set into training and make evaluation unreliable.

## XGBoost

XGBoost is a gradient-boosted decision-tree algorithm.

This implementation uses:

```python
XGBClassifier(
    n_estimators=300,
    max_depth=6,
    learning_rate=0.05,
    subsample=0.8,
    colsample_bytree=0.8
)
```

These are reasonable educational starting parameters, not guaranteed optimal hyperparameters for every dataset.

## Decision thresholds

The model outputs a probability such as:

```text
P(fraud) = 0.73
```

A threshold converts that probability into a class.

For example:

```text
threshold = 0.50
0.73 >= 0.50 → fraud
```

A lower threshold such as `0.30` flags more transactions as potentially fraudulent.

### Why tune the threshold?

In fraud detection:

**False negative (FN):**
Actual fraud → model says legitimate.

Possible consequence: financial loss and undetected fraudulent activity.

**False positive (FP):**
Legitimate transaction → model flags it as fraud.

Possible consequence: legitimate customers may experience transaction declines, additional verification, or manual review.

Therefore, the threshold should be selected according to the organization's fraud-loss cost, customer-experience cost, and available investigation capacity.
